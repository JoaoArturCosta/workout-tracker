# Use an explicit workout and set state machine

Each planned set will be Pending, Completed, or Skipped, and each workout will be Active, Completed, Partial, or Discarded. The first Pending set in the fixed set sequence is the Current set. Only its checkbox can change set state. Checking a non-final Current set validates and completes it, then starts rest when another Pending set remains. Checking the final Pending set validates and opens the Finish confirmation; Cancel leaves it Pending, while Confirm atomically completes it and ends the workout as Completed only when every planned set is Completed, or Partial when any set is Skipped. Skip Set moves the Current set to Skipped without starting rest, and Restore returns a Skipped set to Pending before the workout ends. Undo can return only the latest Completed set to Pending before another completion, and it cancels that set's rest and alert. Ending early produces a Partial workout. Discard is a confirmed Controlling-device action that ends the workout, invalidates its Rest period and alert, hides it from normal history, and excludes every set from analytics and Prior set values. The system retains an immutable internal Discarded record rather than hard-delete it so offline replay, revisions, and retries remain safe. Ended and Discarded workouts accept no changes. Explicit states and guarded transitions require more schema and API work than the current completed booleans, but they prevent ambiguous progress, duplicate rest jobs, and edits after a workout ends.
