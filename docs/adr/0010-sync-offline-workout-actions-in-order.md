# Sync offline workout actions in order

The Controlling device will store the frozen workout plan, local state, and a first-in-first-out action outbox in IndexedDB. Each write action will carry a unique operation ID, the controlling-device epoch, and the expected workout revision. Queued actions will chain their expected revisions through the local ordered sequence. The server will apply each action in a transaction, deduplicate retries, validate the requested state change, and return the next revision; it will reject stale revisions and old controlling devices rather than use last-write-wins. Alert delivery and telemetry writes will not change the workout revision. Device handoff will require an empty acknowledged outbox, then atomically change control and increment the controller epoch. Replace lost device will instead keep only server-acknowledged state, invalidate rest and alerts, and increment the epoch after an online data-loss confirmation; if the old device returns, its stale writes enter the existing Sync-conflicted recovery and cannot overwrite or merge into server state. Finishing offline will make the local workout immutable and Sync-pending; the server will mark it ended only after accepting the ordered final-set and Finish action. Discarding offline will require confirmation, invalidate rest locally, queue an ordered idempotent Discard action, and lock the workout as Sync-pending; the server's immutable Discarded record becomes canonical only after acknowledgement. If the server rejects an action for a stale revision or controller epoch, the device will stop before that action, preserve its local snapshot and full outbox, make the workout read-only, and show Resolve sync; it will not discard, reorder, merge, or process later actions. Resolve sync will allow review or export, cancellation that remains read-only, or Use server version after clear confirmation. Use server version will finish writing a read-only Recovery archive before clearing local work or loading server state; if archive creation fails, resolution stops and the workout remains Sync-conflicted. V1 will keep one immutable Recovery archive per conflicted workout until explicit export or deletion, including across refresh and logout. It will not evict an archive under storage pressure; it will block new offline work and require export or deletion, while warning that clearing the PWA or site data still removes device-only archives. V1 will not force local state, automatically merge or rebase, or retry a true stale conflict. Reconnecting will not send expired rest alerts. This adds revision and outbox handling, but prevents retry duplication, stale-device writes, invalid workout states, and late alerts.
